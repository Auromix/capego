# 本地工作台与处理原型

状态：第一版软件实现。实体采集、生产吞吐和算法精度不在本轮已验证范围。

## 工作台

页面直接由接收服务提供，无 CDN、在线字体、前端构建或浏览器模型下载。默认本机访问；LAN 访问需要令牌。令牌仅保存在当前页面内存，刷新页面后重新输入。

页面按三个工作阶段组织：采集与处理、检查标注、数据集。采用浅色纸面、深绿色文字和状态色，列表与画面并排；窄屏改为上下排列。处理按钮显式启动任务，页面刷新只查询状态。

采集页显示包数量、存储体积、完成状态和双路 RGB 统一时间轴。检查页显示质量结论、结果来源、任务/操作描述、时间范围、关联物体 ID 和检查修订。数据集页保存命名快照并导出。

当前原型以逐帧预览为主，还没有连续视频播放器、轨迹叠加或逐关节编辑器。后者不属于已确认的首版人工操作要求。

## 独立处理

`capego process` 可在接收服务停止时直接处理 PC 已落好的数据。Web 启动同一处理模块的后台线程，不阻塞 HTTP 接收线程。SQLite 索引是两者的共享元数据，原始文件保持不变。当前一次服务实例默认一个处理 worker，避免争抢 GPU。

每次显式提交产生 batch ID，每条采集产生独立 processing ID。开始时和执行时都检查原始数据完整性。未完成输入单独拒绝；执行失败写入该任务错误，不影响其他任务。异常退出中断的 queued/running 任务不会自动重新处理，用户可重新提交生成新版本；旧状态需结合服务进程判断，尚未实现跨进程租约恢复。

### 后端

- `quality`：按声明频率检查缺样/间隔，检查图像曝光和对比度，计算双目时间戳差。时间戳差不是硬件同步测量。语义与几何缺失明确标记。
- `synthetic`：仅接受 origin=synthetic 的采集；产生已知测试语义、物体框、21 关节、腕部和相机位姿。它是数值测试夹具，不是视觉识别算法。
- `local_vlm`：读取 CAPEGO_MODEL_ROOT 下提前准备的 Qwen2.5-VL 模型，离线采样最多 8 帧，生成受数据契约约束的任务/操作/物体结果。采样不能保证发现所有短动作，全部结果要求检查。不会输出假定准确的 3D 几何。真实模型验证状态见验证报告。

三维手部和相机轨迹的真实估计仍需选定算法并结合实际标定验证；当前禁止用模拟几何冒充 sensor/replay 的真实结果。

## 数据与检查

区间统一使用相对采集开始的纳秒，半开 `[start_ns,end_ns)`；物体框为指定视角的归一化 xyxy。操作必须落在所属任务内，左右手操作可以重叠。对象只存相关 ID，不推断 ID 列表顺序的角色含义。

处理结果在 `processing/<id>/result.json`，保存来源摘要、质量结果和后端。检查修订单独保存在 SQLite，写入时检查 expected_revision，过期修改返回冲突。每次修订保留完整有效文本和区间；旧处理结果不变。

数据集快照冻结选中片段、处理摘要和检查状态；后续修改检查结果不影响旧快照。未检查但质量通过、无需处理问题的片段可纳入；排除或未解决的问题片段拒绝。当前同一数据集不接受重叠来源区间，避免任务和子操作重复计数；重叠操作本身仍保留在标注中。

HDF5 保留选中区间内原生 RGB/IMU 采样、传感器时间、时钟 ID、标定与标注。EgoWAM 导出需要连续有效的 RGB、左右腕部和相机位姿，按目标采样率对齐并过滤无效范围；人工点击可用不能替代缺失几何。
