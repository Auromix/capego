# 后处理、检查与数据集版本

> 状态：本页保存逐项确认的产品行为。2026-09-24 已实现处理任务、检查修订和数据集快照原型，见[实现边界](../system/workbench-v1.md)和[验证记录](../validation/2026-09-24-software.md)。真实几何估计、标注质量和生产性能仍待验证。

## 处理入口与批次

用户在工作台选择一条或多条采集记录，主动启动完整后处理。可选记录必须满足[录制结束且完整落盘](../system/overview.md#录制结束与数据完成分开表示)的条件；新数据到达不会自动启动处理。

一个批次统一启动，各条采集独立处理、独立记录状态和结果。某条失败不影响其他条的结果，支持单独重试。批次是处理操作的组织方式，不把多次采集合并成没有边界的连续记录，也不直接等同于数据集。

默认不要求指定任务列表或填写提示。用户可以在启动前补充“本批主要是整理桌面、装盒”等背景；提示作为识别参考，不能代替实际观察。批次并发数量、阶段重试和中间结果复用机制待设计。

## 自动产出

| 类别 | 首版已确认范围 | 待定义内容 |
| --- | --- | --- |
| 任务与片段 | 任务描述、任务边界、任务内操作及其边界；同一任务内操作可在时间上重叠 | 分类规则、任务之间的重叠关系、精确时间语义及边界修正联动 |
| 双手运动 | 每手 21 个三维关键点、手腕位置与朝向，支持两种空间表达，附质量与来源信息 | 点位命名和索引、坐标轴、单位、姿态表示、频率、质量字段和精度 |
| 操作语义 | 每条操作保留参与手、动作、相关物体 ID 列表和起止时间；动作采用自然语言描述并可附可扩展标签，物体关系保留在描述中 | 初始动作词表、标签编码与扩充规则、物体命名及字段编码 |

所有数值和语义输出都需要区分原始观测、算法估计与人工修正。缺失信息不能伪装成有效观测，模型估计也不直接成为机器人动作真值。

后处理同时估计相机自身的运动轨迹并记录质量和有效性，用于关联两种手部空间表达。参考系含义和待定义的变换约定见 [Ego 数据设计](ego-data.md#双手运动的空间参考)。

双手输出的具体范围见[双手的标准输出](ego-data.md#双手的标准输出)。部分结果缺失与其余结果分别标记，保留有效内容，按目标训练入口要求携带有效性掩码或筛选时间窗口，见[部分缺失数据的使用](ego-data.md#部分缺失数据的使用)。具体质量阈值、掩码编码与窗口筛选条件仍待设计。

### 任务与操作两层分段

采用“任务片段 → 操作片段”两层组织，例如“把杯子装进盒子”包含“拿起杯子、放进盒子、合上盒盖”。两层引用原始采集的时间范围，不为分段重复保存源视频；读取和导出时按所需层级取数据。

同一任务内的操作片段允许在时间上重叠，不要求所有操作串行排列。例如“左手扶住盒子”和“右手放入杯子”可分别记录为同时发生的两条操作；“双手共同搬盒子”可以记录为一条双手操作。

每条操作保留参与手（左手、右手或双手）、动作、相关物体 ID 列表和起止时间。物体 ID 的引用遵循[物体标注范围](#物体标注范围)中的采集与处理版本约束。字段编码，以及并行与共同操作的识别规则仍待细化。

首版只记录相关物体 ID 列表，物体之间的具体关系保留在自然语言描述中，不增加被操作对象、目标对象或工具等结构化角色字段。例如“右手把杯子放进盒子”关联杯子和盒子的 ID，放入关系由描述表达；列表顺序不承载这些角色含义。

不能可靠识别的部分保留“未确定”标记，不强行生成标签。两层片段不受存储分块边界限制。任务片段之间是否允许重叠、精确边界语义和边界修正联动仍待定义；本轮确认的操作重叠不自动决定任务之间的关系。

### 动作描述与标签

首版采用“自然语言描述＋可扩展动作标签”。例如保留“右手把杯子放进盒子”的描述，并可附上“放入”标签。标签用于归类，描述保留动作的具体内容，不要求首版词表预先覆盖所有动作。

区分以下情况：

- 能可靠描述动作且有对应标签时，同时保留描述与标签。
- 动作可以描述，但词表没有合适标签时，保留描述，标签可以暂缺；不强行归入已有类别。
- 动作识别不可靠时，保留“未确定”标记并进入检查，不用看似完整的描述或标签掩盖不确定性。

“没有合适标签”和“未可靠识别动作”分别表达；仅因词表未覆盖，不把整条操作判为未确定。数据集准入与导出仍遵循各自的质量和目标输入要求。

初始动作词表、标签标识与编码、同义词归并、扩充方式和版本引用规则仍待设计。本节不选择具体标注模型，也不将上述示例冻结为完整词表。

### 物体标注范围

第一版采用“二维框＋跟踪 ID”表达物体位置与身份，用于区分并持续指向操作中的同一个物体，同时保留物体名称、时间和有效性信息。

二维框关联对应的视频帧、时间和相机视角。首版不要求像素级物体轮廓掩码，也不要求物体的精确三维位置和朝向；轮廓掩码可在后续扩展。

跟踪 ID 在同一次采集、同一处理版本内统一维护，任务和操作片段引用对应轨迹及其时间范围，不因任务切分或片段边界调整而重新编号。例如连续跟踪到同一个杯子时，“拿起杯子”和“放入盒子”引用同一个 ID。引用时需同时明确采集和处理版本，不能仅凭相同的 ID 值关联不同采集或不同版本的物体。

ID 的维护范围不代表始终能够确认物体身份。物体离开画面后再次出现，若无法确认是否为原物体，可以生成新 ID；不强行连接无法确认身份的轨迹。不同采集独立维护，重新处理后的 ID 不默认与旧版本一一对应。

二维框的坐标约定、字段与输出频率，以及跨视角匹配、跟踪中断后的关联判定和关联结果表达，仍待设计。框关联相机视角不等于已经支持跨视角身份匹配；也不宣称已支持跨采集物体身份匹配。

### 本地自动标注方案

VLM 作为任务、操作语义、物体标注及分段建议的主要候选能力；专用视觉与几何算法承担手部三维运动、物体跟踪和时间边界细化等工作。质检结合原始数据与处理结果定位问题。具体模型、算法及分工效果需用样例验证，尚未完成选型。

处理结果保留模型版本、处理参数和来源时间段。模型输出作为自动标注保存，不标记为人工确认或真实标签。参考部署使用[同一台配备本地 GPU 的 Ubuntu PC](../system/overview.md#首版部署与职责)，准备好依赖和模型后无互联网依赖运行。

## 重新处理与人工检查

每次重新处理生成新版本，保留旧结果。人工检查和修正绑定对应处理版本；重跑不得覆盖旧版本的检查成果。已存在的数据集继续引用原版本。处理版本内部的修正历史、保存和并发操作机制待设计。

第一版工作台提供以下检查与修正能力：

- 优先呈现问题片段及原因，其他片段可浏览和抽查。
- 修改任务描述，调整片段起止时间，标记可用或排除。
- 分别保留自动质检结果和人工检查状态；未检查内容明确标记为未人工检查。

首版暂不加入逐帧三维轨迹编辑。质检置信度定义、问题排序、抽样策略以及允许人工确认的问题范围，后续细化。

## 数据集准入与版本固定

自动质检通过的片段可以纳入数据集，不要求逐条人工确认。有问题的片段需要人工处理并确认可用；仍有未解决问题或已被排除的片段默认不纳入。导出保留质检结果与人工检查状态，不把自动通过写成人工通过。哪些完整性或质量问题不可通过人工确认放行，仍需明确定义。

部分缺失的数据仍保留有效内容，但不因此跳过上述检查与准入规则。人工确认可用不消除缺失标记，也不豁免目标训练入口的必要字段和有效性要求；各目标导出时分别筛选可用内容。

用户跨采集和处理批次选择内容，先生成命名数据集版本，再选择训练目标导出。生成版本时固定：

| 固定内容 | 用途 |
| --- | --- |
| 原始采集来源和所选片段 | 明确选取了哪些内容及时间范围 |
| 各片段对应的处理版本 | 明确采用哪一次处理结果 |
| 当时的标注、修正、质检及检查状态 | 后续编辑不改变已有数据集 |

后续重新处理或修改标注，需要生成新的数据集版本才会反映到新版本中。同一数据集版本可以多次导出，也可以通过不同适配器导出。这里固定的是数据内容与来源，不承诺不同导出格式产生相同文件字节。

处理批次、处理结果版本和数据集版本各有不同用途，不相互替代。源数据或旧处理版本的清理、引用保护、训练与验证集划分、去重及导出配置记录仍待详细设计。

## 训练接入边界

固定数据集内容和导出训练格式是两个明确步骤。适配器负责按具名目标训练工程要求转换和校验；通用容器或字段名称相同，不等于动作语义匹配或训练可用。

接下来围绕 ego 数据明确观测、手部动作、语义、质量和来源，再用目标训练仓库的实际输入核对样本与导出要求。当前验收是 ego 数据能够被读取并实际参与最小训练，不规划机器人数据，也不要求复现模型效果。具体建议见[WAM 训练接入](training-integration.md)。当前没有选定目标或已验证兼容声明。
