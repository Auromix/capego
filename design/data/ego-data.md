# Ego 数据结构、时间轴与空间参考

> 状态：本页记录确认的数据原则。2026-09-24 原型已采用纳秒时间、SI 单位、wxyz 四元数和 x 向右/y 向下/z 向前的相机参考约定，见[采集协议](../system/protocol-v1.md)及[处理实现](../system/workbench-v1.md)。当前几何来源为合成测试夹具，真实重建与同步尚未验证；不因字段已实现而声称实际数据已满足精度要求。

## 一次采集的数据内容

一次采集对应一个独立文件夹，分块保存并统一读取，生命周期见[总体架构](../system/overview.md)。数据按以下四类组织；此处描述逻辑关系，不选择实际文件名或容器格式。

| 类别 | 内容 | 与其他数据的关系 |
| --- | --- | --- |
| 采集信息 | 唯一标识、起止时间、设备信息、采集设置、分块索引及完整性状态 | 标识一次采集，组织其原始数据和处理来源 |
| 原始观测 | 各路 RGB 视频、逐帧时间戳、IMU 样本 | 按各传感器实际采样的内容与时间保留，通过统一时间轴关联 |
| 标定信息 | 相机内参、畸变参数、传感器间的位置与朝向、标定版本 | 明确解释该次采集所需的几何关系 |
| 后处理结果 | 双手运动、相机运动轨迹、任务与操作片段、物体标注、质量结果和人工修正 | 绑定处理版本，并能追溯到原始采集的具体时间范围 |

原始数据与处理结果分别保存。重新处理、检查修正和数据集版本的关系遵循[处理与数据集设计](processing.md)。具体传感器数量和配置继续按硬件设计讨论，本页不把客户候选规格转为已冻结配置。

## 原始采样与统一时间轴

确认采用“保留原始采样、统一时间关联、导出时按需对齐”的原则。

1. 每次采集使用一条统一时间轴，以本次录制起点为相对时间零点。跨存储块不重置该时间轴。
2. 按传感器采样时刻组织观测，保留原始时间戳及其到统一时间轴的映射。映射的表达与计算方式仍待设计。
3. PC 接收时间用于接收和传输诊断，不替代采样时间。重传、补传和落盘先后不改变原始采集时间关系。
4. 视频和 IMU 各自保留实际采样的内容与时间，不预先压成相同频率；一个视频帧附近的多个 IMU 样本仍按原始样本保留。
5. 缺帧、断流等缺口在统一读取时保留，不因拼接存储块而被掩盖。

统一时间轴是数据表达原则，不意味着传感器已经实现硬件同步，也不代表已达到某个误差指标。曝光时刻的定义、硬件触发、时钟偏差与漂移、精度测量仍待同步设计和验证。

多次采集各有自己的时间范围和来源，批量处理不会将它们自动拼成一条连续采集时间轴。

## 双手运动的空间参考

首版支持以下两种三维表达，并保留相机运动轨迹及有效性信息：

| 参考系 | 含义 | 用途 |
| --- | --- | --- |
| 相机坐标系 | 手部相对于当前相机的位置和朝向 | 与视频对应、投影检查以及按训练需要取用 |
| 本次采集的局部参考系 | 手部相对于该次录制中建立的固定空间参考的位置和朝向 | 分析手部运动，区分设备运动与手部运动 |

例如手停在桌上而佩戴者转头，相机坐标中的手部位置也会变化。后处理需要估计相机自身的位置和朝向随时间的变化，用于关联两种表达；相机运动属于算法估计结果，保留对应处理版本和有效性信息。

局部参考系只针对本次采集，不要求全球定位，也不默认跨采集对齐。建立固定空间参考是表达目标，不是无漂移或精度保证。具体参考相机、原点、轴方向、单位、变换方向与存储方式仍待定义。

估计失败的部分明确标记为无效。相机轨迹、相机坐标手部结果和局部参考系手部结果分别记录可用性，不能以虚构的零位姿替代失败结果。后续需要定义跟踪中断、重定位或坐标参考改变时的分段与关联方式，不强行拼接无法确认空间关系的轨迹。

这一决定增加相机运动估计及其质量检查的设计范围，尚未选择定位或手部算法。它不增加物体精确三维位姿要求；物体首版范围仍见[处理与数据集设计](processing.md#物体标注范围)。

## 双手的标准输出

每只手采用“21 个三维关键点＋手腕位姿＋质量信息”作为首版标准输出：

| 内容 | 已确认含义 |
| --- | --- |
| 左右手身份 | 标识佩戴者的左手或右手，不按图像中的左右位置命名 |
| 21 个三维关键点 | 手腕 1 点，五根手指各 4 点，描述手指形状与运动 |
| 手腕位姿 | 手腕的位置和朝向，描述整只手的运动；单个手腕关键点的位置不能代替朝向 |
| 质量与来源 | 表达有效、缺失、插值等状态，记录估计算法与处理版本；置信度需有明确含义 |

关键点和手腕位姿按前述相机坐标与本次采集局部参考系提供。遮挡、出画或跟踪失败时允许部分结果缺失，并分别标记有效性；固定关键点布局不要求每个时间点都能恢复全部点，也不把预测或插值当成真实观测。

关键点的精确名称、索引、连接关系、朝向约定、质量字段粒度、置信度来源及编码仍待设计。这里只确定输出结构，尚未选择具体手部模型；不把参考某种关键点布局等同于采用对应算法。

## 部分缺失数据的使用

默认保留部分有效数据，按训练入口的要求筛选。不因短暂出画、局部遮挡或单只手估计失败而丢弃整次采集。

- 按时间、左右手和关键点分别保留有效性；视频、IMU、相机轨迹和不同空间表达的手部结果也各自记录可用性。
- 被质检标记为问题的片段进入人工检查，遵循[数据集准入规则](processing.md#数据集准入与版本固定)。保留数据不等于自动纳入数据集；人工确认可用后，缺失标记仍然保留。
- 目标训练入口支持并实际使用有效性掩码时，可以携带掩码导出部分有效结果；目标要求完整双手动作时，筛选满足要求的时间窗口。人工确认不能替代目标要求的必要数据。
- 补零、预测或插值不能标记为真实观测，也不能据此把无效数据改成真实有效数据。保留原始内容及处理来源。

具体质量阈值、掩码字段与编码、窗口筛选和插值策略仍待设计。训练验证需确认导出的有效内容实际参与训练，不能以全部被掩码忽略的样本作为接入成功的证据。

## 训练导出时的对齐

导出器按目标训练工程的要求选择参考时间、采样频率和样本窗口，按需对齐、重采样或插值。插值是可选的处理方式，不默认用于补齐所有缺失数据。

导出需明确标记缺失和插值结果，并能追溯所用原始样本及处理来源。插值、算法估计与真实采样分别表达，不覆盖原始数据。目标可使用哪些结果，按[训练接入验证](training-integration.md)确定。
