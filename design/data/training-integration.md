# WAM 训练接入要求

> 状态：首版验证 ego 数据能够实际接入开源 WAM 训练；不纳入机器人数据规划或模型效果复现。目标工程、版本和具体测试条件待确认，当前没有已实现或已验证的训练适配器。

## 产品要求

CapEgo 导出的数据集应能实际接入典型开源 WAM 的训练流程。首版先完整打通一个具名开源训练工程，固定版本并验证数据读取和最小训练流程，预留其他导出适配器的扩展能力；不要求首版同时验证多个目标。具体目标和训练用途仍待确认。通用数据格式可作为内部或中间表达，训练接入需要落实到具体工程。

本项目采集自然人类双手操作，后处理生成结构化人手动作。目标模型如何使用这些观测和动作，需要依据其训练入口定义，不能预设它们等同于任何机器人的关节或末端控制指令。

本轮范围聚焦 ego 数据从采集、处理、导出到训练使用的可用性。机器人数据准备、混合比例、机器人控制及部署效果不纳入当前设计，也不作为本轮验收的前置条件。若候选默认配方需要机器人数据，应核查是否有可独立使用 ego 数据的训练入口或可行适配；不能要求用户先补充机器人数据。

不以复现论文指标、证明模型质量提升或得到高成功率策略作为首版接入完成条件。数据字段、时间关系、有效性和来源仍需要正确，既有自动质检与人工检查要求继续适用。选择目标是为了核对数据确实可用，不将一个候选工程的全部训练需求都扩展为 CapEgo 的产品范围。

## 选择训练目标时需要核对

| 核对项 | 需要得到的答案 |
| --- | --- |
| 训练代码 | 哪个官方仓库、哪个版本提供需要的训练或微调入口，运行条件是什么 |
| 训练用途 | ego 数据参与该 WAM 的哪条实际训练路径和哪项有效损失；与自然双手数据是否匹配 |
| 观测 | 需要哪些视角、图像处理、时间关系、标定或状态字段 |
| 动作 | 动作主体、坐标系、单位、时间含义及有效性要求；是否需要额外映射 |
| 标注与样本 | 任务描述、片段边界、采样窗口、缺失数据和质量筛选的要求 |
| 数据集组织 | 目标数据读取器接受什么格式和元信息，训练与验证数据怎样组织 |
| 可复现条件 | 模型与依赖准备、训练配置、资源要求、输入版本和运行说明 |

首版目标数量已确定为一个，具名目标、变体和兼容范围尚未确定。选择有实际训练代码且输入语义与本项目数据匹配的目标，将是后续设计的一项明确决策。

## 训练算力约束

用户明确“一般算力”以 **RTX 5880 Ada 48GB 这样的单卡**为参考。首版训练接入按该级别的一张 GPU 设计和验证，不以多卡机器为必要前提；这是一项参考预算，不要求只能使用该型号。CPU、内存、磁盘、驱动、软件环境及可接受训练时长仍待明确。

该预算针对训练接入，后处理的模型组合与参考 PC 配置仍需按处理负载确定，也没有要求训练与所有后处理模型同时驻留显存。训练验证可以使用另行准备的同级单卡环境。

候选需要满足 ego 数据输入匹配、公开训练代码与可复现步骤、单卡预算内的有效训练，并核对第三方复现及维护证据。接口匹配或显存容量相同，只能支持可行性判断，不能代替实测或社区成熟度证据。

## 建议的接入验证

以下是验证方案草案，不代表测试已经执行，也不替代后续按目标工程确定的验收条件。

1. 固定目标训练仓库的版本、模型与依赖、训练配置，以及 CapEgo 数据集版本和导出配置。
2. 使用真实参考场景采集、处理和检查得到的数据完成导出，检查观测、动作、时间关系及必要标注的语义和有效性。
3. 使用目标工程实际的数据读取器读取导出结果，构成其训练入口所需的有效批次。
4. 在约定单卡环境中，使用 CapEgo 的 ego 样本运行目标 WAM 的最小训练或微调过程，覆盖前向、损失计算、反向传播和参数更新；确认这些样本对有效损失及参数更新有实际贡献，记录结果。
5. 给出可重复执行的命令和配置，保留已验证范围、已知限制和输入版本，供其他开发者复现。

单卡验证建议分开记录以下层级，具体样例、步数和阈值待确认：

| 层级 | 需要的证据 | 不能据此宣称 |
| --- | --- | --- |
| 数据接入检查 | 目标 loader 读取真实导出数据，字段、时间和监督语义正确 | 已完成训练或效果验证 |
| 最小有效训练 | 在约定单卡上，ego 样本实际参与目标 WAM 的有效训练；损失、梯度及参数更新可核查，保存检查点；记录峰值显存和耗时 | 已复现论文效果、模型质量提升或适用于所有数据 |

上述两个层级落实首版已经确认的“数据读取和最小训练流程”。精度、批量、序列长度和训练配置的调整需要记录。具体启用哪些损失由目标工程的 ego 训练路径决定，不预设必须对全部导出字段同时施加监督。应列明实际使用的字段、未使用的字段及其原因；例如仅验证视频训练路径时，不能同时声称手部动作字段也通过了训练验证。不能把 ego 样本全部屏蔽或仅作为旁路文件加载后宣称其已参与训练。

文件可以解析、形状可以拼接、数据可以预览，分别只证明对应环节可用。训练接入通过需要实际训练路径的运行证据；论文效果复现、模型质量提升和机器人部署效果均不属于当前验收范围。

训练验证遵循上述单卡预算，Ubuntu 24.04 接收 PC 的部署要求不自动等于训练环境已经具备。具体适配器、文件格式和动作映射将在目标选择后设计。

## 首个目标的候选核查

2026-09-22 只读检查了官方资料和部分训练、数据代码，尚未下载模型、执行训练或验证 CapEgo 数据。以下保留候选研究依据，不是已确认的目标选型；其中机器人示例仅说明上游工程现状，不转化为本项目的数据准备要求。

| 候选 | 已查到的接入依据 | 对 CapEgo 的含义 |
| --- | --- | --- |
| EgoWAM | 人类数据键映射、位姿变换、世界与动作训练配置，以及本地数据读取方式 | 数据主体匹配的候选；社区成熟度和一般算力可复现性尚不足以支持冻结为首选 |
| DreamZero | 新机器人数据到 GEAR 的转换、模态配置和训练入口 | 公开指南的状态与动作示例面向机器人，不代表自然人手数据已直接兼容 |
| Cosmos Policy | ALOHA 数据读取与训练路径，读取机器人状态和控制动作 | 相机布局与动作语义均需额外适配，本轮不建议作为优先目标 |
| OpenWAM | 自定义数据接口、训练入口、动作有效性 mask 和 video-only 接入说明 | 通用框架备选；本次核查未找到现成自然双手 reader 与完整转换配方 |

EgoWAM 本次代码核查版本为 `c87617fe37a6ed6a951e6b176ad552200c425c93`。其 [Human 数据映射与变换](https://github.com/GaTech-RL2/EgoWAM/blob/c87617fe37a6ed6a951e6b176ad552200c425c93/egowam/rldb/embodiment/human.py) 从 `left/right.obs_ee_pose` 构造未来动作序列，并使用 `obs_head_pose` 转换参考坐标；这些是观测到的人手运动，不是机器人控制日志。数据中保存手部关键点，不代表该训练分支直接监督全部手指关节。

若选 EgoWAM，需要继续明确手部参考点与朝向、头部／相机运动的获取与坐标关系、采样时序和未来预测目标。其 [世界模型训练入口](https://github.com/GaTech-RL2/EgoWAM/blob/c87617fe37a6ed6a951e6b176ad552200c425c93/egowam/hydra_configs/train_zarr_wm.yaml) 和 [混合数据示例](https://github.com/GaTech-RL2/EgoWAM/blob/c87617fe37a6ed6a951e6b176ad552200c425c93/egowam/hydra_configs/data/cup_saucer/indomain_wm.yaml) 包含人类与机器人分支。后续仅核查和适配 ego 数据的有效训练路径，不将其默认混合配方照搬为产品要求；该路径尚未验证。仅跑通该仓库独立的 BC 基线，不能作为 WAM 训练入口已经接通的证据。

官方 [数据说明](https://github.com/GaTech-RL2/EgoWAM/blob/c87617fe37a6ed6a951e6b176ad552200c425c93/docs/data.md) 提供本地 episode 读取方式；实际配置还需核对模型下载和日志依赖，不能仅因支持本地数据就宣称全流程已验证离线。模型变体、精确训练环境和最低资源尚未选定，不据此确定 CapEgo 后处理 PC 的显卡配置。

### EgoWAM 的成熟度与算力核查

上轮优先建议主要基于数据接口匹配，不能据此推断已经过充分社区复现，或普通消费卡能够完成训练。2026-09-22 核查得到：

- [仓库元信息](https://api.github.com/repos/GaTech-RL2/EgoWAM) 显示创建于 2026-09-06，当次查询为 32 stars、2 forks；公开 main 有 5 次提交，尚无发布版本。该仓库从研究代码库导出，提交数量不能代表此前全部研究工作，但本次没有找到足够独立复现记录来支持“社区充分验证”。
- [论文附录 B.3](https://arxiv.org/html/2607.08436v1#A2.SS3) 报告多数变体用单张 L40S、Pixel-PT 用两张 L40S，每任务每方法约两天。[作者资源回复](https://github.com/GaTech-RL2/EgoWAM/issues/2#issuecomment-5704151381) 明确 BC、DINO、3D Flow 使用一张 L40S，Pixel-PT 使用两张，约三天。两者都是作者报告，具体差异未解释，不能改写为本项目实测时间。
- 同一论文的 RTX 4090、30 Hz 属于移除世界模型头后的策略推理。它不证明单张消费卡能完成原配置训练，也不代表完整世界预测推理的吞吐。
- 快速检查使用小切片，不等于训练收敛或复现论文效果；原始视频到手部位姿、头部轨迹和可选 3D Flow 的准备成本应另行测量。论文人类数据使用 Aria 及 MPS，不能当作本项目自行搭建、全本地后处理已验证的依据。

因此保持候选状态。用户随后明确 RTX 5880 48GB 级别单卡预算。该卡与作者采用的 L40S 都是 Ada 架构、48GB 显存，支持将 DINO 和 3D Flow 列入单卡可行性验证；这是基于硬件规格和作者训练报告的推断，没有在 RTX 5880 上实测。不能直接沿用 L40S 训练耗时；作者采用两卡的 Pixel-PT 配方不作为首版单卡已可用方案。参考 [RTX 5880 官方规格](https://www.nvidia.com/en-us/products/workstations/rtx-5880/) 和 [L40S 官方规格](https://www.nvidia.com/en-gb/data-center/l40s/)。算力范围明确后，社区复现不足的问题仍然存在，具体目标尚未确定；当前只验收 ego 数据可用性，不要求复现上述论文效果。

其他候选的核查入口：

- [Cosmos Policy ALOHA loader](https://github.com/NVlabs/cosmos-policy/blob/main/cosmos_policy/datasets/aloha_dataset.py)：机器人 qpos、action 和多相机数据读取。
- [OpenWAM 自定义数据接入](https://github.com/OpenWAM-Official/OpenWAM/blob/90e94ae31efddd64b59e00365cfc501d9a972eb1/assets/openwam_usage_docs/benchmark-integration.md)：视频、动作、状态、mask 及自定义 reader 接口；动作缺失时应按其契约屏蔽监督，不能将占位值当成有效动作。

公开资料后续可能变化；进入适配设计时需固定实际代码版本，并核对对应的数据读取器和训练入口。
