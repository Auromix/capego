# 后续设计讨论

产品头脑风暴及首轮总体设计讨论已完成，确认结论分别维护在[产品定义](product/scope.md)、[总体架构](system/overview.md)和[处理与数据集设计](data/processing.md)。当前尚未进入实现。

## 已明确的设计起点

- 一台佩戴采集设备加一台 Ubuntu 24.04 PC；PC 承担接收、后处理和工作台，完整后处理以本地 GPU 为参考配置。
- 一次录制在 PC 上对应一个文件夹，边采边持续传输，PC 持续接收并分块保存，读取时拼接为该次录制的统一时间线。设备缓存只暂存未获 PC 可靠保存确认的数据，随确认持续释放；断连恢复后补传。
- 开始录制前须确认 PC 已连接且能够接收保存；条件不满足时不开始采集并提示原因。录制途中断连仍继续缓存，恢复后补传。
- 正常采集按缓存不耗尽设计；缓存满属于异常，直接结束本次录制并保留原因与已有数据。异常结束后恢复连接只自动补传，不自动续录或创建新录制；完整性以补传和校验结果为准。
- 采集接收与后处理独立运行。只处理录制已结束且全部数据完整落盘的记录，用户选一条或多条主动启动，各条独立执行、失败可重试。
- 重新处理保留旧版本；任务与操作两层分段，产出双手运动、物体及操作语义和质量结果。物体先采用二维框与跟踪 ID，保留名称、时间和有效性，不要求像素级轮廓掩码；VLM 是语义标注主要候选方向。
- 物体跟踪 ID 在同一次采集、同一处理版本内维护，任务与操作片段引用，边界调整不重新编号。身份无法确认时可生成新 ID，不默认跨采集或跨处理版本对应。
- 同一任务内的操作片段允许时间重叠；左右手并行操作可分别记录，双手共同完成同一动作可记为一条双手操作。每条保留参与手、动作、相关物体 ID 列表和起止时间。
- 动作采用自然语言描述并可附可扩展标签；词表未覆盖时保留描述，标签可暂缺。识别不可靠才标记为未确定并进入检查，不把缺少合适标签等同于识别失败。
- 操作中的物体关系保留在自然语言描述中；首版只关联物体 ID 列表，不增加被操作对象、目标对象或工具等结构化角色字段，列表顺序也不表达角色。
- 问题片段优先检查，其他可抽查；支持描述和边界修正、可用及排除。自动质检通过的数据可纳入，保留是否人工检查的状态。
- 先固定数据集内容版本，再按目标训练格式导出；后续修改不能改变已有数据集版本。
- 首版先完整打通一个具名开源 WAM 训练工程，验证数据读取和最小训练流程，预留其他适配器；具体目标尚未选择。
- 训练算力参考 RTX 5880 48GB 级别单卡，不以多卡为首版必要前提；目标选择同时核对 ego 数据匹配、社区复现和实际资源消耗。
- 当前只验证 CapEgo 的 ego 数据能被目标工程读取并实际用于最小训练，不纳入机器人数据规划、混合训练配方或模型效果复现。
- Ego 数据包含采集信息、原始观测、标定和后处理结果。保留各传感器实际采样及原始时间戳，用单次采集的统一时间轴关联；导出时按需对齐，缺失和插值均有标记。详见 [Ego 数据设计](data/ego-data.md)。
- 双手三维数据支持相机坐标与本次采集局部参考系两种表达，同时保留相机运动轨迹和有效性信息；定位和手部算法尚未选择。
- 每只手输出 21 个三维关键点、手腕位姿、左右手身份及质量来源信息；允许部分结果缺失，保留有效性标记。
- 部分缺失时保留有效内容，问题片段仍按规则检查；导出按训练入口要求携带有效性掩码或筛选满足条件的时间窗口。人工确认不消除缺失标记，补零、预测或插值不冒充真实观测。

首次准备可联网，日常运行无互联网依赖。客户的传感器和性能指标仍是候选输入，没有转为首版强制验收条件。

## 建议的下一阶段顺序

1. 继续细化手部点位命名、单位、姿态、质量与来源字段。操作已采用自然语言描述、可扩展标签和相关物体 ID 列表；初始词表及扩充机制、任务之间的关系、边界修正联动、物体跨视角及中断后的关联、质量阈值、有效性掩码编码和窗口筛选条件仍待设计。
2. 按约定单卡预算核对候选开源 WAM 对这些 ego 字段的使用，选择首个目标和版本并设计最小训练验证；不把机器人数据准备或训练效果评估作为当前前置问题。
3. 细化已确认起录条件的检查方式、缓存容量与传输预算、时间与同步、分块和完整性、保存确认、补传与断电恢复，以及 PC 存储不足等其余异常行为。缓存耗尽已确定为异常结束本次录制。
4. 细化处理和检查界面、错误恢复、版本引用与清理、去重和训练集划分。
5. 通过代表性样例确定质量和性能要求，再选择硬件、具体模型、GPU、协议、文件格式及部署技术。

每轮集中澄清一个关键问题，将确认结论写回所属正文。上述顺序是推进建议，不代表已经选定训练模型、组件或验收指标。
