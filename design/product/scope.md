# 产品定义与范围

> 状态：2026-09-22 产品头脑风暴结论已确认；详细系统设计、实现和验证尚未完成。

## 定位与首版使用者

captureego 面向开源开发者和研究者，提供一套可复现、可扩展的第一视角采集与数据集生产方案。一个开发者能够独立完成自然双手操作的记录、本地自动处理、检查和数据集生产，得到包含结构化双手动作、能够接入典型开源 WAM 训练的数据集。

首版以个人或单个实验台为参考场景，从桌面物体操作开始。打开盒子、拿取和摆放物品、双手传递是场景示例，具体验证任务尚待选择。

交付方式以完整参考方案为主，同时保留更换采集设备、处理工具和导出方式的空间。硬件材料清单、搭建文档、处理流程和数据集示例应围绕同一参考方案形成可复现体验；适配范围及其验证条件后续逐项定义。

## 已确认的产品行为

| 环节 | 已确认的要求 |
| --- | --- |
| 开始与暂停 | 人按按钮后持续采集，直到暂停；自然进行双手操作，采集前无需输入或选择任务 |
| 视角与场景 | 头戴或胸戴第一视角；首个参考场景为桌面物体操作 |
| 传输与保存 | 在采集过程中，持续向采集设备所连接的同一局域网中的另一台 Ubuntu 24.04 PC 传输数据，并在该 PC 落盘保存 |
| 后处理启动 | 用户选择一批记录，一次主动启动完整后处理流程；新数据接收和落盘不自动触发后处理 |
| 自动处理与标注 | 任务识别、片段划分、结构化双手动作提取及相关标注属于后处理；启动后由系统自动执行 |
| 人工检查 | 以检查为主，优先看问题片段、其余抽查，允许少量纠正和补充 |
| 数据治理 | 跨多次采集、多个处理批次筛选和组合数据 |
| 数据集版本 | 保存命名数据集版本，能够重复导出相同内容 |
| 训练接入 | 导出的数据集必须能够实际接入典型开源 WAM 的训练流程；目标仓库、版本及对应输入要求随后确定 |
| 主要入口 | 可视化工作台覆盖日常操作，命令行为进阶入口；具体界面技术尚未选定 |
| 本地运行 | 首次下载软件、模型和依赖允许联网；准备完成后，采集、处理、标注、治理和导出全流程无互联网依赖 |

## 采集与处理的边界

Ubuntu 24.04 PC 是首版明确的持续接收与落盘端。记录在采集期间持续保存到该 PC，暂停不作为开始传输的触发条件。采集端是否保留缓存、如何处理局域网中断和 PC 不可用，属于后续系统设计问题。

存储接收与后处理具有不同的启动方式：数据持续接收，后处理等待用户选择批次并发起。启动一批后，由系统自动运行整批处理。后来收到的数据保持待处理，等待用户发起相应处理批次。

后处理、检查、治理和数据集生产在本地计算环境中完成。处理算力是否由接收 PC 同时提供、工作台运行在哪里，尚未决定。无互联网依赖仍允许并需要设备间的局域网通信。

## 数据交付目标

首版需要覆盖视频、IMU、标定信息等基础观测，以及结构化双手动作和相关标注。双手三维关键点、手腕位置与姿态是已讨论的数据类型；具体关键点集合、坐标系、单位、频率与精度要求尚待定义。处理结果需要表达估计置信度、缺失情况及人工复核记录。

模型估计、人为修正和原始观测各有不同来源。自然人手动作与机器人动作的转换关系，需要按目标训练任务明确；不以填充或重命名字段替代缺失的观测及动作映射。

WAM 训练接入是首版交付要求，目前尚未选定训练仓库，也未验证兼容性。具体输入和验证建议见[训练接入要求](../data/training-integration.md)。

## 尚需设计的边界

- 采集时的局域网连接、接收 PC 可用性、持续保存状态、异常提示及数据缺失处理；采集端缓存需求。
- 相机、安装细节、同步机制、传输协议、文件组织和后处理部署。
- 手部动作与标注的精确字段、质量门槛、问题判定及少量人工修正的具体操作；三维动作编辑能力尚未确定。
- 数据集版本如何固定内容与处理来源，以及目标训练入口、适配方式和验证条件。
- 成本、重量、续航、性能、时间表，以及软件、硬件、文档和示例数据的许可证。

客户候选性能指标仍是需求输入，见[客户候选规格](customer-inputs.md)。完整用户旅程见[使用流程](workflow.md)。本页描述产品要求，不代表已实现、已通过测试或用户验收。
