# 产品定义与范围

> 状态：截至 2026-09-24 逐项确认的产品与系统设计行为；详细接口、选型、实现和验证尚未完成。

## 定位与首版使用者

CapEgo 面向开源开发者和研究者，提供一套可复现、可扩展的第一视角采集与数据集生产方案。一个开发者能够独立完成自然双手操作的记录、本地自动处理、检查和数据集生产，得到包含结构化双手动作、能够接入典型开源 WAM 训练的数据集。

首版以个人或单个实验台为参考场景，从桌面物体操作开始。打开盒子、拿取和摆放物品、双手传递是场景示例，具体验证任务尚待选择。

交付方式以完整参考方案为主，同时保留更换采集设备、处理工具和导出方式的空间。硬件材料清单、搭建文档、处理流程和数据集示例应围绕同一参考方案形成可复现体验；适配范围及其验证条件后续逐项定义。

## 已确认的产品行为

| 环节 | 已确认的要求 |
| --- | --- |
| 开始与结束 | 按开始且起录检查通过后创建一次采集及 PC 上的独立文件夹，持续采集并分块保存，按结束封闭本次录制；再次开始创建新记录，无需预先指定任务 |
| 视角与场景 | 头戴或胸戴第一视角；首个参考场景为桌面物体操作 |
| 传输与保存 | 在采集过程中，持续向采集设备所连接的同一局域网中的另一台 Ubuntu 24.04 PC 传输数据，并在该 PC 落盘保存 |
| 后处理启动 | 用户选择一条或多条已结束且完整落盘的采集主动启动；各条独立处理，新数据到达不触发处理 |
| 自动处理与标注 | 生成任务与操作两层片段、双手运动、物体及操作语义、质量结果；默认自动识别，可选填背景提示 |
| 人工检查 | 优先问题片段、其余抽查；支持任务描述修正、边界调整、可用和排除标记，首版不含逐帧三维轨迹编辑 |
| 数据治理 | 跨多次采集、多个处理批次筛选和组合数据 |
| 数据集版本 | 先固定片段、处理版本和当时标注修正，再导出训练格式；后续修改不改变旧数据集 |
| 训练接入 | ego 数据须被目标开源 WAM 读取并实际参与最小训练；当前不规划机器人数据或要求模型效果复现，目标仓库和版本待定 |
| 主要入口 | 可视化工作台覆盖日常操作，命令行为进阶入口；具体界面技术尚未选定 |
| 本地运行 | 首次下载软件、模型和依赖允许联网；准备完成后，采集、处理、标注、治理和导出全流程无互联网依赖 |

## 采集与处理的边界

首版同一台 Ubuntu 24.04 PC 承担接收存储、后处理和工作台，完整后处理以本地 GPU 为参考配置。开始录制前须确认 PC 已连接且能够接收保存。设备边采集边持续传输，PC 持续落盘，作为原始数据的正式保存位置。设备只临时缓存尚未得到 PC 可靠保存确认的数据，随确认持续释放，并在断连恢复后补传。起录、分块、缓存和处理准入规则见[总体架构与采集保存](../system/overview.md)。

采集接收与后处理独立运行。后处理等用户选择完整采集记录并启动，各条独立执行、失败可单独重试；重新处理保留旧版本。收到新记录不自动启动后处理。

后处理、检查、治理和数据集生产均在本地完成，具体规则见[处理与数据集设计](../data/processing.md)。无互联网依赖仍允许并需要设备间的局域网通信。

## 数据交付目标

首版覆盖视频、IMU、标定等基础观测，以及双手三维关键点、手腕位置与朝向、任务与操作片段、物体及操作语义、质量结果。具体字段、坐标系、单位、频率与精度要求尚待定义。物体范围为名称、二维框和跟踪 ID；ID 在同一次采集、同一处理版本内维护，任务与操作片段引用，详见[物体标注范围](../data/processing.md#物体标注范围)。处理结果表达估计置信度、缺失及人工检查记录。

模型估计、人为修正和原始观测各有不同来源。自然人手动作与机器人动作的转换关系，需要按目标训练任务明确；不以填充或重命名字段替代缺失的观测及动作映射。

WAM 训练接入是首版交付要求，目前尚未选定训练仓库，也未验证兼容性。具体输入和验证建议见[训练接入要求](../data/training-integration.md)。

## 尚需设计的边界

- 局域网连接、保存确认、完整性校验、缓存容量、断电恢复、异常提示和资源边界。
- 相机、安装细节、同步机制、传输协议、文件格式、具体处理模型及 GPU 配置。
- 手部动作与标注的精确字段、质量门槛、问题判定和可人工确认的问题范围。
- 数据集版本固定与来源管理的实现，以及目标训练入口、适配方式和验证条件。
- 成本、重量、续航、性能、时间表，以及软件、硬件、文档和示例数据的许可证。

客户候选性能指标仍是需求输入，见[客户候选规格](customer-inputs.md)。完整用户旅程见[使用流程](workflow.md)。本页描述产品要求，不代表已实现、已通过测试或用户验收。
