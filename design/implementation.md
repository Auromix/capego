# 首个可运行版本的实施与验证

> 2026-09-24：用户授权开始实现、分阶段提交 GitHub。下列为本轮工程计划；完成状态以验证报告为准。

## 实现顺序

1. 建立 Python 包、版本化数据契约、模拟双目 RGB / IMU 来源和测试环境。
2. 实现独立接收服务、逐条持续传输、设备临时队列、可靠保存确认、重传去重、录制结束和完整性校验。
3. 实现统一读取、显式启动的独立处理批次、自动质量检查、标注适配器、人工检查记录和不可变数据集快照。
4. 实现本地浏览器工作台与 CLI，覆盖接收状态、处理、检查、数据集和导出。
5. 实现具名训练目标的数据适配与可执行验证入口，分别记录模拟数据契约检查、真实模型读取和实际训练证据。
6. 在 macOS 执行单元、故障与端到端测试；核查无影远程测试入口，并提供 Ubuntu 24.04 可复现运行方式与 CI。

## 本轮实现选择

- Python 3.11+，通过 HTTP 接收持续发送的数据包；接收服务、采集发送循环与后处理职责独立。
- 本地 Web 工作台由接收服务提供静态资源，无 CDN 或在线字体依赖；后台处理由用户显式启动。
- PC 以采集文件夹保存原始数据，SQLite 维护持久状态和索引。设备暂存未确认数据；服务可靠保存并返回匹配内容摘要后，设备释放相应缓存。
- 使用模拟视频和原生时间轴上的 IMU 样本测试传输、读取与处理。模拟观测和模拟几何结果携带显式来源标记。
- 真正的 VLM、手部三维重建和相机轨迹由适配器提供；缺少模型或标定时报告缺失，不输出伪造的真实估计结果。
- 不在本轮凭模拟数据宣称硬件同步、相机指标、真实标注精度或 RTX 5880 训练兼容已经通过。

## 验证重点

- 录制未结束时 PC 已收到且保存数据；确认后设备缓存随传随释放。
- 断连、丢失确认和重复发送不会丢失或重复原始数据；不同内容重用同一数据包标识应拒绝。
- 缓存耗尽异常结束录制；已有数据继续补传，不自动重新起录。
- 未结束、缺包或校验失败的记录不能进入后处理；完整记录可按原始时间统一读取。
- 一条处理失败不阻塞同批其他记录；重跑保留旧版本。
- 检查状态与质检结果分别保存；数据集版本固定后不被后续修改影响。
- 导出能追溯来源、处理版本与选择条件；真实训练验证缺少依赖或硬件时明确失败，不以模拟成功代替。
